# Careers Page Redesign — Design Spec

**Date:** 2026-08-07
**Project:** Randy's Painting & Drywall (vanilla PHP/MySQL XAMPP app)

## Goal

Fix the "wall of text" problem on the public careers page: each open
position currently renders as a full-length card (description,
responsibilities, requirements — often 300+ words, including a boilerplate
paragraph of served towns repeated on every card) in a 3-column grid, making
the page hard to scan and the cards wildly uneven in height. Split the page
into a compact listing + a per-position detail page, matching the pattern
already established by the blog (`blog.php` → `blog-post.php`) and the
gallery (`gallery.php` → `project.php`).

## Decisions (from brainstorming)

- **Compact card + separate detail page.** `careers.php` becomes a listing
  of short cards (title, employment type + pay, a short excerpt, a "View
  details & apply" link). A new `career.php?id=X` page shows the full
  description/requirements for that one position.
- **Apply happens on the detail page**, not back on the listing. The
  application form (name, email, phone, experience, availability, message,
  resume upload) moves to `career.php`, scoped to the one position from the
  URL — no position dropdown needed. The existing modal on `careers.php` is
  removed entirely.
- **No schema changes.** `job_positions` keeps its current columns (`title`,
  `description`, `requirements`, `employment_type`, `pay_range`, `status`).
  The card excerpt is generated by truncating `description` to ~160
  characters at a word boundary (plus "…") — no new "excerpt" column, so the
  4 existing live postings need no admin re-entry.
- **New `.job-card` style**, not a reuse of `.service-card` — keeps this
  change isolated from the Services page. Card title uses the existing
  global `.mkt h3` size (no custom `font-size` override), avoiding the
  specificity bug already hit and fixed once this session on the blog cards
  (a bare `.job-card__title { font-size: ... }` would lose to `.mkt h3`
  exactly like `.blog-card__title` lost to `.mkt h2`).
- **Sitemap parity.** `career.php?id=X` URLs for every open position are
  added to `sitemap.php`, mirroring the existing blog-post and
  project-detail loops.

## Architecture

### 1. `careers.php` (trim down)

- Keeps the page-hero and the open-positions query (`SELECT * FROM
  job_positions WHERE status = 'open' ORDER BY created_at DESC`).
- Removes: the apply modal, the POST-handling block (validation, resume
  upload, DB insert, email notification, `?applied=1` confirmation), and the
  `?position=` query-param handling — all of that moves to `career.php`.
- Grid of `.job-card` elements, each a link to `career.php?id=X`:
  - Title (h3)
  - Meta line: `<?= $EMPLOYMENT_LABELS[$type] ?> · <?= $pay_range ?>` (pay
    range omitted when null, same as today)
  - Excerpt: `job_excerpt($position['description'])` (new helper, see below)
  - "View details & apply →" link
- Empty state ("No open positions right now…") unchanged.

### 2. New helper — `job_excerpt()`

Added to `includes/marketing.php` (where other small marketing-page helpers
already live):

```php
/** First ~160 chars of a job description, cut at a word boundary, for card teasers. */
function job_excerpt(string $description, int $limit = 160): string
{
    $description = trim(preg_replace('/\s+/', ' ', $description));
    if (mb_strlen($description) <= $limit) {
        return $description;
    }
    $cut = mb_substr($description, 0, $limit);
    $lastSpace = mb_strrpos($cut, ' ');
    if ($lastSpace !== false) {
        $cut = mb_substr($cut, 0, $lastSpace);
    }
    return $cut . '…';
}
```

### 3. New `career.php?id=X` (detail + apply)

- Loads the position: `SELECT * FROM job_positions WHERE id = ? AND status
  = 'open'`. Missing/closed/invalid id → 404 branch (friendly not-found
  message + link back to `careers.php`), matching `blog-post.php`'s
  not-found pattern.
- Page hero: breadcrumb `Home / Careers / <title>`, eyebrow = employment
  type label, `<h1>` = position title.
- Body section:
  - Meta line (employment type · pay range)
  - Full description (`nl2br(e($description))`, same rendering as today)
  - Requirements block (same `nl2br(e($requirements))`, same conditional as
    today)
  - Application form (same fields/order as the current modal form: name,
    email, phone, years_experience, availability, message, resume), with a
    **hidden `position_id` input** fixed to this position (no dropdown)
  - On success: same DB insert + `send_job_application_notification()` call
    as today, then redirect to `career.php?id=X&applied=1`, which shows a
    "Thanks for applying!" confirmation card instead of the form (same copy
    as today's confirmation, reusing the `.form-card` style)
  - "← Back to open positions" link

### 4. Styles — `assets/css/styles.css`

New rules, modeled on `.blog-card` structurally but without an image:

```
.job-grid { display: grid; grid-template-columns: repeat(auto-fit, minmax(280px, 1fr)); gap: 1.5rem; margin-top: 2rem; }
.job-card { display: block; background: #fff; border-radius: 16px; padding: 1.75rem; box-shadow: 0 1px 3px rgba(22,35,63,.08), 0 8px 24px rgba(22,35,63,.06); text-decoration: none; color: inherit; transition: transform .2s ease, box-shadow .2s ease; }
.job-card:hover { transform: translateY(-4px); box-shadow: 0 4px 12px rgba(22,35,63,.12), 0 16px 40px rgba(22,35,63,.10); }
.job-card__meta { font-size: .8rem; color: var(--muted); text-transform: uppercase; letter-spacing: .04em; margin-top: .4rem; }
.job-card__excerpt { color: var(--muted); font-size: .95rem; margin-top: .75rem; }
```

(`.job-card h3` picks up the existing global `.mkt h3` size/weight — no
override, per the decision above.)

### 5. Sitemap — `sitemap.php`

After the existing gallery-photo loop, add one for open job positions:

```php
foreach (db()->query("SELECT id, updated_at FROM job_positions WHERE status = 'open'")->fetchAll() as $job) {
    $ts = strtotime((string) ($job['updated_at'] ?? ''));
    $urls[] = [
        'loc'        => $origin . url('career.php?id=' . (int) $job['id']),
        'lastmod'    => $ts ? date('Y-m-d', $ts) : $today,
        'changefreq' => 'monthly',
        'priority'   => '0.6',
    ];
}
```

## Data flow

1. Visitor loads `careers.php` → open positions query → compact `.job-card`
   grid with generated excerpts.
2. Visitor clicks a card → `career.php?id=X` → single position (must be
   `status='open'`) loaded → full description/requirements + application
   form rendered.
3. Visitor submits the form → same validation/upload/insert/email flow as
   today, scoped to this one position → redirect to
   `career.php?id=X&applied=1` → confirmation card.
4. Visitor clicks "← Back to open positions" → `careers.php`.

## Error handling

- `career.php` with a missing, non-numeric, closed, or nonexistent `id` →
  HTTP 404 + friendly not-found message + link back to `careers.php` (same
  pattern as `blog-post.php`).
- Application form validation errors (missing fields, bad email, missing or
  oversized or non-PDF resume) → same messages as today, re-rendered on
  `career.php` above the form.
- 0 open positions → existing empty state on `careers.php`, unchanged.

## Testing

- Manual, against the local DB (currently 0 open positions — will need at
  least 2-3 temporarily inserted via the admin Careers panel or SQL to
  verify the grid/detail flow, then removed if they were only for testing):
  - `careers.php` shows compact, roughly-uniform-height cards with a short
    excerpt (not the full description) for each open position.
  - Clicking a card's "View details & apply" goes to `career.php?id=X` and
    shows the full description + requirements + application form.
  - Submitting a valid application (with a PDF resume) saves the row,
    sends the notification email, and shows the confirmation card.
  - `career.php?id=<closed-or-missing>` returns a 404 with the not-found
    message.
  - `sitemap.php` lists one `career.php?id=` URL per open position.
  - `index.php`'s hiring-card link and `careers.php`'s empty state are
    unaffected.

## Out of scope (YAGNI)

- An `excerpt`/summary admin field — auto-truncation is enough for now.
- Closed-position pages, position categories/tags/filtering.
- Changing the admin Careers panel (position create/edit/list) — it keeps
  working against the same `job_positions` table/columns as today.
